## Deliberately NOT included (and why)

- `.env` — contains machine-specific values. Use `.env.example` instead and create your own `.env`. See "Secrets" below.
- `node_modules/` — restored with `bun install` (or `npm install`) from `bun.lock`.
- `.next/` — build output, regenerated by `bun run build`.
- `.git/` — repository metadata (24 MB). History intentionally excluded so no historical secrets can leak. Initialize a fresh repo with `git init`.
- `skills/`, `tool-results/`, `download/`, `dev.log` — sandbox/platform artifacts, not part of the website.
- No separate database backup files existed in the project; `db/custom.db` is the complete, live database.

## Quick start (local)

```bash
bun install          # or: npm install
cp .env.example .env # then set AUTH_SECRET (see below)
bun run db:push      # sync schema (optional — db/custom.db is already populated)
bun run dev          # http://localhost:3000
```

Default admin (only on a FRESH database): `admin` / `DoDigitals@2025` — change it immediately
in Admin → Account. The shipped `db/custom.db` already contains the real admin account.

## Secrets — how to configure safely

1. Never put real secrets in files you commit or share.
2. Copy `.env.example` to `.env` for local development; fill in:
   - `DATABASE_URL` — local: `file:../db/custom.db`
   - `AUTH_SECRET` — generate with `openssl rand -base64 32`
3. On Vercel: Project → Settings → Environment Variables — add `DATABASE_URL`,
   `AUTH_SECRET` (and optionally `ADMIN_PASSWORD`, `ADMIN_ALLOWED_ORIGINS`, `APP_URL`).
   Values live on Vercel's servers, never in the repository.
4. Full details: `README-DEPLOY.md` (database options, deployment steps, troubleshooting).
